# 중복 병합·D07 수정 및 DB/API 재검증

검증일: 2026-10-26. 기준: `fix/week3-results`의 `6c122e5` + 이 PR의 수정.

## 변경 내용

Trivy의 여러 레코드가 동일한 GHSA를 명시하고 OSV의 한 레코드와 연결되면, 기존 일대일 매칭에서는 동일 취약점이 여러 Findings로 남을 수 있다. 같은 패키지·버전이며 각 Finding의 GHSA 집합이 동일한 단일 값인 경우에만 추가 병합한다.

- 서로 다른 GHSA, 여러 GHSA, CVE만 공유하는 모호한 관계, NSWG-ECO-516은 기존처럼 분리·검토한다.
- 원문·식별자·심각도 관측·수정 후보·설치 연결은 보존한다. 남아 있는 외부 모호 관계도 검토 대상으로 유지한다.
- `deduplication`에 병합 전후 건수와 ID를 기록하고 기존 Findings API의 `normalization`에서 반환한다.
- `merged_pairs`는 기존 일대일 매칭 수다. 추가 병합으로 감소한 수는 `removed_duplicate_count`다.

D07에서는 오류 상태·오류 코드 등과 함께 실패 당시 구성 입력을 `priority_evaluations.attempted_payload`에 저장한다. 구성 전 실패는 SQL NULL이다. 입력은 진단 자료이며 정상 계산 결과가 아니다. 오류 설명은 임의 예외 원문 대신 단계별 고정 메시지를 사용하고 `message_policy=safe-stage-summary-v1`로 표시한다. 상세 입력은 공개 API에 추가하지 않는다.

[재실행 안내 및 전체 근거](../verification/week5-dedup-d07/README.md)를 참고한다. JUnit은 테스트 210개와 하위 검증 153개를 합해 363개로 표시한다. Starlette/httpx 사용 중단 예정 경고 1개가 있으며 실패는 없다.

## 적용 순서

1. 기존 DB에 수정된 `db/oss_closeup_v2_2_priority.sql`을 적용한다. `ADD COLUMN IF NOT EXISTS`이므로 기존 행을 보존하고 반복 실행할 수 있다.
2. 수정된 worker를 배포한다. 초기화 파일 변경만으로 기존 DB가 자동 갱신되지는 않는다.
3. 새 scan_id로 검사한다. 변경된 정규화 결과로 기존 검사를 덮어쓰지 않는다.

현재는 검토용 변경이다. 운영 DB 변경·배포·EC2 전체 흐름 검증은 수행하지 않았다.

## 미확정 및 제외 범위
