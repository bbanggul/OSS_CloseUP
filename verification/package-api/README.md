# 패키지 API 검증

[화면 연동 계약](../../docs/package-api-v1.md)을 먼저 참고한다.

저장소 루트에서 실행:

```sh
sh verification/package-api/run.sh
```

Docker Compose가 Python/PostgreSQL 이미지와 의존성을 준비하고 임시 DB·API에서 전체 worker 테스트, 기존 29사례 회귀 검사, 신규 API의 실제 HTTP 요청을 차례로 실행한다. 호스트 포트·운영 DB·프로젝트 `.env`는 사용하지 않는다. 종료 시 이 실행의 컨테이너를 정리하고 로그와 응답은 무시되는 `results/`에 남긴다. 같은 체크아웃에서 동시에 여러 번 실행하지 않는다.

## 검증 내용

- 같은 버전의 복수 설치, 버전 없음·생태계·버전 차이의 분리, 안정적인 묶음 ID.
- 대표 등급의 후보 여부와 고유 취약점 수에 따른 정렬, UNKNOWN 순위 없음.
- 검색·심각도·관계 필터 및 500개 초과 목록의 페이지 이동 후 전체 순위 유지.
- 상세에서 하위 등급을 포함한 전체 취약점의 설치별 수정 후보·출처 보존.
- 처리 중·정상 0건·부분 결과·실패 구분 및 미연결 취약점 보존.
- 우선순위 실패와 원본 근거 변경 시 과거 등급·순위 숨김.
- 읽는 도중 다른 연결이 평가 상태를 바꾸는 경우의 repeatable-read 일관성 및 다음 요청의 409 스냅샷 충돌.
- 명시적인 동일 검사 병합 이력만 최종 ID로 연결, 모호한 이력은 409, 모르는 ID·다른 검사 ID는 404.
- 검토 완료 근거·현재 정규화 fingerprint·미해결 검토 항목에 따른 중복 검토 상태.
- DB 장애는 503, 잘못된 쿼리는 422.

## 근거

`evidence/summary.json`, `worker-tests.txt`, `worker-junit.xml`에 통과 수와 실행 로그를 저장한다. `http-results.json`에는 신규 API의 실제 요청 응답과 20개 대조 결과가 있다. `service-results.json`은 기존 29사례·38변형의 340개 회귀 대조다. `source-manifest.json`은 실행 시 소스·검증 파일의 해시다. 큰 JSON은 공백만 줄이고 입력·응답·기대값을 유지했다.

모든 추가 DB 데이터는 합성 입력이다. 실제 사용자 업로드부터 자동 worker 실행, EC2, 브라우저 화면, 외부 스캐너/AI 호출은 이번 검증 대상이 아니다. 중복 병합·D07 수정 PR과 독립된 기준 브랜치에서 실행하므로 해당 PR의 테스트 수와 합산하지 않는다.
